## 2. 三种运行模式

### `IDLE`

用于：

- 连接和断开设备；
- 启动反馈轮询；
- 手动调试四条调平腿；
- 方位轴故障复位、使能、失能、低速运行；
- 举升电缸手动运行；
- 角度和位置置零。

手动调试必须处于 `IDLE`，避免和自动控制循环同时发送命令。

### `LOCAL_LEVELING`

入口是 `启动本地调平阶段`。

要求：

- 倾角传感器已连接；
- 四条调平腿全部连接。

控制逻辑：

1. 读取当前 X/Y 倾角；
2. 计算角度误差；
3. 根据车体长宽换算四腿速度；
4. 叠加四腿扭转误差修正；
5. 以某一条“最高腿”为参考腿；
6. 进入死区后保持约5秒；
7. 完成后自动停止。

默认参数：

- 死区：`0.002 deg`
- `Kp = 0.2`
- 抗扭增益：`0.01`
- 最大调平电机速度：`150 rpm`
- 保持时间：`5 s`

此阶段不包含早期脚本中的触地和预顶升流程。

### `MPC`

启动时会：

1. 强制要求选择 CSV 记录文件；
2. 启动反馈轮询；
3. 重置 MPC 内部速度记忆；
4. 将当前传感器 Z 角作为 MPC 的相对零点；
5. 周期生成目标轨迹；
6. 求解 MPC；
7. 把系统级角速度分发到三个执行系统。

注意：源码的 `start_mpc_control()` 没有强制检查所有硬件是否连接，未连接的执行器只会被跳过。因此实际使用时必须自行确认连接和反馈正常。

## 3. MPC控制逻辑

MPC内部状态不是直接使用五个角度，而是先构造阵面方向向量：

```text
S = [0, 0, -1]
当前方向 = Magzᵀ · Magxᵀ · Magyᵀ · Mbᵀ · Maᵀ · S
```

MPC参数：

- 状态维度：`Nx = 3`，即 `[Rx, Ry, Rz]`
- 控制维度：`Nu = 4`
- 预测步长：`Np = 3`
- 控制步长：`Nc = 2`
- 实际采样周期：`T = 0.20 s`

控制量顺序：

```text
U[0]：调平 X 轴角速度，rad/s
U[1]：调平 Y 轴角速度，rad/s
U[2]：方位角速度，rad/s，正值为逆时针
U[3]：举升/俯仰角速度，rad/s
```

MPC求解的是控制增量：

```text
ΔU = [未来控制量相对当前 U 的变化]
U_new = U_old + ΔU_first_step
```

目标函数主要包含：

- 方向向量跟踪误差；
- 控制增量惩罚；
- 调平 X/Y 通道的附加正则项。

约束包括：

- 四个系统级角速度限幅；
- 当前角度和角度限位推导出的动态速度限幅；
- 每次控制增量限幅；
- NaN/无穷值保护。

求解器使用 OSQP。

当前速度上限约为：

| 通道 | 上限 |
|---|---:|
| 调平X | `0.04745 deg/s` |
| 调平Y | `0.0611 deg/s` |
| 方位 | `3.5 deg/s` |
| 举升 | `3.9 deg/s` |

## 4. 目标轨迹

[`target_trajectory.py`](<./MPC_fixed/target_trajectory.py:26>) 默认执行：

1. 俯仰角从当前目标逐渐升到 `60 deg`；
2. 俯仰阶段约持续 `20 s`；
3. 之后开始方位运动；
4. 方位最大角速度为 `3.0 deg/s`；
5. 俯仰最大角速度为 `3.4 deg/s`；
6. 加速段时间均为 `2 s`。

目标轨迹最终不是输出角度，而是转换成未来3步的方向向量：

```text
[Rx1,Ry1,Rz1, Rx2,Ry2,Rz2, Rx3,Ry3,Rz3]
```

实际总控调用时使用 `MPCController.T = 0.20 s` 作为预测间隔。

## 5. 执行器映射

### 调平

系统级角速度先换算为四腿线速度：

```text
v_pitch = 0.5 × 车长 × X角速度
v_roll  = 0.5 × 车宽 × Y角速度
```

四腿分配：

```text
leg0 =  pitch - roll
leg1 =  pitch + roll
leg2 = -pitch + roll
leg3 = -pitch - roll
```

之后按照丝杠导程 `5 mm`、减速比 `5` 换算为电机 rpm，最后限制到 `±150 rpm`。

腿编号和正负方向必须通过低速实机确认。

### 方位

方位角速度换算：

```text
rpm = rad/s × 60 / (2π) × motor_gear_ratio
```

当前：

```text
motor_gear_ratio = 1.0
max_rpm = 1.0
```

方位正值定义为逆时针。

方位轴使用 CiA402 风格控制字：

- 速度模式；
- 使能顺序 `0x0006 → 0x0007 → 0x000F`；
- 目标速度使用 `0x60FF/F0DA`；
- 实际位置使用 `0x6064/F010`；
- 状态字使用 `0x6041/F003`。

### 举升/俯仰

MPC输出 `lift_rate_rad_s` 后：

1. 转换成 `deg/s`；
2. 根据当前俯仰角查询前馈增益表；
3. 计算前馈 rpm；
4. 用俯仰角速度误差进行 PID 修正；
5. 发送电动缸速度。

默认：

- 电动缸最大速度：`2200 rpm`
- PID `Kp=50`
- PID修正限幅：`50 rpm`
- 角速度目标上限：`4 deg/s`
- 角速度滤波系数：`0.5`
- 控制发送周期：`0.15 s`

俯仰角由独立编码器读取，支持软件置零和多圈累计。

## 6. 保护和停止行为

总控中已有以下保护：

- 俯仰角低于 `40 deg` 时，实际方位速度强制为零；
- 俯仰角达到 `69 deg` 时停止举升；
- MPC连续3次求解失败时全部停止；
- 上一次有效MPC命令超过 `1 s` 未更新时全部停止；
- MPC异常或输出非有限值时，MPC内部输出归零；
- `stop_all()` 会停止调平、方位和举升，举升停止命令重复发送3次。

特别注意：

- `停止控制循环` 只停止调度和日志，不自动向执行器发送零速；
- 硬件停机应使用 `全部停止/急停`；
- 当前 MPC 内部俯仰角上限是 `65 deg`，反馈线程安全停止阈值是 `69 deg`，两者不是同一个限制。

## 7. 推荐使用流程

1. 安装 Python 3.10+ 和依赖：

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r .\MPC_fixed\requirements.txt
   ```

2. 启动：

   ```powershell
   .\.venv\Scripts\python.exe .\MPC_fixed\main.py
   ```

3. 点击“刷新所有端口”。

4. 连接设备：

   - 倾角传感器：默认 `230400`
   - 四条调平腿：默认 `115200`
   - 方位控制器：默认 `115200`
   - 举升电缸：默认 `115200`
   - 俯仰编码器：默认 `115200`

5. 启动反馈轮询，确认角度、位置、速度和方位状态字刷新。

6. 在 `IDLE` 下低速验证：

   - 四腿编号和方向；
   - 方位逆时针/顺时针；
   - 举升上升/下降；
   - 故障复位、使能、停止；
   - 调平、方位、俯仰置零。

7. 先运行本地调平，确认四腿动作正确。

8. 再选择 CSV 文件并启动 MPC。

9. 实验结束时点击“全部停止/急停”。

## 开环验证的定义

严格开环不能直接“按角度停下”，因此流程是：

```text
标定点：俯仰角 ↔ 缸位移 / 固定 rpm 下所需时间
        ↓
输入目标角
        ↓
查表得到目标位移或运行时长
        ↓
固定速度单次运行后停止
        ↓
只读取最终俯仰角并计算误差
```

之后可额外提供“编码器位移辅助停止”模式，用于比较纯开环与行程反馈辅助的误差；两者会明确区分，避免把辅助模式误写成开环。

## 接口与接线约定

电脑只通过 USB 与设备通信；Windows 会把 USB 转串口设备识别为 `COMx`，测试程序选择的是 COM 口，不是直接选择 USB。

建议使用两路独立 USB 转串口：

| 设备 | 电脑侧接口 | 程序中的连接 |
|---|---|---|
| 举升电动缸驱动器 | USB 转串口 / USB 转 RS485 | “举升缸 COM 口” |
| 俯仰角度编码器 | USB 转串口 / USB 转 RS485 | “俯仰编码器 COM 口” |

具体操作会写入每个程序的说明中：

1. 设备断电后完成动力线、编码器线、通信线和急停连接。
2. 接入 USB 转串口后，在“设备管理器 → 端口(COM 和 LPT)”记录两个 COM 号。
3. 依次拔插 USB，确认哪个 COM 对应举升缸、哪个对应俯仰编码器。

## 实物操作顺序

1. 运行 `00`，确认两个 USB 串口的 COM 映射。
2. 运行 `01`，观察静止读数至少 30 秒；手动缓慢移动机构时，确认电机编码器和俯仰编码器都有对应变化。
3. 运行 `02`，从最低 rpm、最短脉冲开始；记录“正 rpm 对应俯仰角增大还是减小”。若方向相反，停止后修正测试配置，不直接修改 MPC。
4. 运行 `03`，低速接近下端和上端安全位置，人工按“记录端点”；得到可用行程、俯仰角范围和标定原始数据。
5. 运行 `04`，每个速度、每个方向至少重复 3 次，得到 rpm—缸速度—俯仰角速度数据。
6. 运行 `05`，逐步缩短脉冲或降低 rpm，记录能稳定分辨的最小位移和最小角度变化。
7. 运行 `06`，基于阶段 03–05 的标定输入目标角；程序执行一次严格开环运动，之后只读取最终角度并记录误差。

阶段 06 会区分两种模式：

- 严格开环：固定 rpm、固定时长，不依据俯仰反馈中途修正；
- 行程反馈辅助：按电机编码器位移停止，用来比较实际可达到的误差，但不称为严格开环。

## 8. 开环角度测试的限制

`lift_06_open_loop_angle.py` 不是闭环定位：

1. 从 `03` 加载端点 JSON；
2. 从 `04` 加载同方向、同载荷条件下的速度 JSON；
3. 根据目标角、当前电机位移、线性标定和固定速度计算一次运行时长；
4. 固定 rpm 运行；
5. 停止后才读取俯仰角并计算误差。

它不会在运动中根据俯仰角修正。

使用 `06` 前，必须恢复与 `03` 相同的电机零点和机械参考位置；否则位移参考不一致，开环结果无效。程序拒绝超过 `2 s` 的单次开环运动，首次只验证小角度、小行程。
